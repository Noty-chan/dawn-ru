## Статус передачи

Это законченный редактируемый срез с проходящими тестами, **не завершённая миграция и не готовый релиз**. Пользователь попросил срочно передать работу из-за лимитов. Новые файлы синтаксически закончены; незавершённых команд изменения файлов нет. Ветка предназначена для продолжения разработки и проверки до слияния в main.

В исходной рабочей копии уже была неотслеживаемая папка `source/supplements/`. Она не относится к этой работе, не изменялась и не включается в коммит. Сначала проверяйте `git status`; не удаляйте её.

## Решения пользователя

1. Развиваем только LionWing. Старая редакция остаётся для завершения текущих игр.
2. Недопустимые игровые действия блокируются с уведомлением. Нарратор может отдельно исправить ОД, ХП и другие значения.
3. Ядро обеспечивает полноценное ручное проведение правил; автоматизация Техник будет использовать те же общие операции.
4. Ядро не должно знать конкретные Техники. Нужны удобные общие инструменты для их ручной реализации и будущей автоматизации.
5. Сохраняем существующий стол, поле, токены, библиотеку и интерфейсные возможности. Миграция идёт частями, без переписывания приложения с нуля.
6. Удобство Нарратора — основной критерий: выбранные источник и цели подставляются, общие параметры вводятся один раз, дополнительные вопросы нужны только при реальном выборе.

## Что изменено

### `apps/companion/lionwing-engine.js`

Отдельный IIFE-модуль `DAWN_LIONWING_ENGINE`, загружаемый после старого `scene-engine.js`. Он сохраняет прежние методы и маршрутизирует `DAWN_SCENE_ENGINE.dispatch`, `dispatchMany`, `previewEvents`, статусы ходов и ряд других методов по редакции Сцены.

Ключевой формат:

```js
const prepared = DAWN_LIONWING_ENGINE.prepare(scene, {
  actorId: sourceId,
  kind: "batch",
  operations: [
    { kind: "resource", resource: "ap", operation: "spend", amount: 1 },
    { kind: "damage", targetId, amount: 5 },
    { kind: "effect", targetId, effect: "negative.помечен" }
  ]
});
// prepared.events передаются существующему commitSceneEvents.
```

Внутреннее событие — `lionwing.command`; результат содержит обычные семантические события для журнала и визуальных эффектов. Операции выполняются на копии. Ошибка отвергает пакет целиком. Есть контроль версии и квитанции повторных ID. Броски подготавливаются до применения, результаты сериализуются; reducer их не перебрасывает.

Состояние хранится в `scene.lionwing` и `actor.lionwing`. Выбор Сопротивления, длительного последствия или клетки может приостановить пакет; хвост хранится в `deferred` и продолжается после ответа. Эти данные переживают нормализацию и сохранение.

Реализованы первоначальные обработчики:

- ОД в начале Хода, обнуление в конце, чередование сторон, Раунды, Прорыв, дополнительные Ходы;
- базовые действия, Шаг с сохраняемым движением, Прыжок, Зарядка, Передышка, основные Атаки;
- общий ручной пакет, расходы/получение ресурсов, точные исправления;
- Броня, Уклонение, урон, лечение, Раны, Сопротивление, Уязвимость, последствия выведения;
- защитные Реакции; повтор Столкновения за 5 урона;
- Эффекты, источники, сроки, временные модификаторы, Настройка ресурсов и часов;
- повторные нанесения урона, пороги здоровья составных NPC, общее движение частей;
- уведомления Наказания, Невидимость, допуски Swift/стоимости и учёт применений для будущих правил;
- XD6, часть общих модификаторов Атак и дополнительные кости для отдельных целей.

**Наличие обработчика не означает завершённый аудит канона или полную поддержку интерфейсом.** В частности, `api.operations` пока неполон относительно switch; привести декларацию возможностей в соответствие с реализацией.

Структурные события поля, маркеров, общих часов и части бросков ещё вызывают старый **одиночный** reducer по allowlist. Старый `dispatchMany` с его триггерами для LionWing не используется. Нужно проверить каждую оставленную делегацию.

### `apps/companion/lionwing-ui.js`

Тонкий адаптер после старых UI/event-модулей, до `app.js`:

- базовые действия во вкладке «Ход» Пульта и в панели героя;
- массовый урон/лечение/Эффекты и ручная Атака с Реакциями во вкладке «Ручное решение»;
- отдельные точные исправления и раскрываемые ресурсы, часы, модификаторы;
- выбор клеток через существующее поле;
- часть старых быстрых кнопок перенаправлена на новые операции;
- используется существующий `commitSceneEvents`, сохранение, журнал и откат.

Использованы обёртки существующих функций и делегированный capture-handler. Это промежуточный адаптер; после проверки желательно заменить хрупкие перехваты явными точками подключения.

### Остальные изменения

- `app-core.js`: редакция Сцены; сохранение LionWing-состояния; Раны больше не обнуляются; Стойкость остаётся `null`.
- `app.js`: пустая Сцена получает выбранную редакцию.
- `network-v2.js`: намерение `lionwing`; проверка владельца; белый список операций игрока; авторитетная подготовка бросков. Исправления остаются Нарратору, ничью Столкновения решает Нарратор.
- `index.html`, `sw.js`: подключение модулей, обновлён dev-кэш.
- `app.css`: оформление новых контролов.
- `tests/lionwing-engine.mjs`, `tests/qa.mjs`: новые проверки и исправление старого ошибочного ожидания, что в LionWing нет Ран.
- `package.json`, `tests/load-scene-engine.mjs`: подключение проверок.

## Следующие шаги — в порядке приоритета

1. Прочитать новый код критически, не считать проходящие тесты доказательством полноты. Сверять только с `source/editions/dawn-en-lionwing-cb2f8e67/canonical/core-rules.json` и каноническими файлами LionWing. Русский перевод старой редакции не является источником новых правил.
2. Закончить браузерный сценарий ручной Атаки с несколькими целями, всеми защитами, Ранами/Сопротивлением, перезагрузкой при ожидающем выборе и откатом. Проверить мобильную ширину и объём кликов.
3. Проверить и устранить оставшиеся обходы ядра: старые кнопки Пульта, инспектор, панель героя, завершение/создание Сцены, импорт, сетевые команды. Не все старые прямые mutator-пути ещё заменены.
4. Укрепить границу редакций. Новая пустая Сцена использует выбранную редакцию, но дефолт настроек ещё старый; добавление персонажей другой редакции в существующий стол пока не защищено полноценно. Сохранить возможность закончить старые игры без случайной миграции.
5. Довести общие механики: Наказание сейчас обнаруживает выход из соседства по началу/концу пути, а не каждому сегменту; Пойман требует полного сопровождения источника; принудительное движение и взаимодействие Эффектов нужно проверить. Расходы альтернативного Фокуса пока не связаны с базовыми действиями автоматически. Дополнительные Ходы/допуски/лимиты имеют API, но не полный удобный UI.
6. Проверить составных NPC глубже: удаление Эффектов со всех частей, сроки, shared-state, редкие защитные комбинации, выбор нескольких частей как одной цели. Обработчик только начальный.
7. Проверить урон, порядок модификаторов, случаи 0 урона, многократные Атаки и сроки защит. Недавно добавленные target-specific dice, Spike и Импровизация с удалением препятствия требуют отдельных тестов.
8. Дуэль намеренно оставлена ручным запросом (в репозитории уже описано расхождение канона), а её полноценное удаление с поля, исход и возвращение ещё не реализованы. Взаимодействие списывает стоимость и записывает действие, конкретный результат назначается общими операциями. Нельзя помечать все действия `full` без честной декларации этих границ.
9. Обновить `ARCHITECTURE.md`, README и автоматизационные карты: текущие документы ещё описывают прежний статус ручного стола. Составить честную карту «операция → доступность в UI → автоматическая часть → ручной выбор». Проверить достаточность операций по 333 Уровням Техник, не автоматизируя их сейчас.
10. Затем завершить сетевой аудит и общий ручной бой, повторить подходящие тесты и только после этого готовить слияние/публикацию.
