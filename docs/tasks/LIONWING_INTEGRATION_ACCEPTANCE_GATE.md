# Обязательный шлюз приёмки LionWing

Этот файл применяется к результатам агентов и ручным изменениям ядра. Зелёный
локальный тест исполнителя не означает, что функция принята.

## Статусы результата

Каждый блок получает ровно один статус:

- **foundation** — API или модель существуют, но приложение их не загружает либо
  настоящий пользовательский путь не подключён;
- **connected** — приложение загружает блок и UI вызывает его через штатный writer;
- **verified** — connected-блок прошёл реальные зависимости, сохранение и нужный
  браузерный/сетевой сценарий;
- **blocked** — известная зависимость не позволяет доказать сценарий.

Слова «готово», «реализовано» и «принято» без статуса запрещены в отчётах.

## Проверка интегратора до merge

### 1. Настоящие зависимости

- Тест использует production `commitScene`, `validateTableEdit`, projection,
  network sanitizer и storage boundary, если функция зависит от них.
- Mock разрешён только для внешней среды. Он не может заменять проверяемый
  контракт функцией, которая всегда возвращает успех или лишь считает вызовы.
- Для каждого mock отчёт объясняет, почему production dependency не применима.

### 2. Один writer

- Определён единственный владелец `version`, undo, journal и persistence.
- Вспомогательный модуль не увеличивает версию и не добавляет undo, если это
  делает `commitScene` или reducer.
- Ошибка на любом шаге оставляет исходную Scene семантически неизменной.

### 3. Полный путь данных

- Проверены UI → intent → sanitizer → authoritative prepare/dispatch → Scene.
- Проверены reload, replay и stale version.
- Если данные относятся к герою, отдельно проверены table backup и hero export;
  один не считается доказательством другого.
- Скрытые данные проверены на player projection и сетевом снимке.

### 4. Негативные сценарии

- отмена;
- повтор события;
- устаревший план;
- отсутствующая цель;
- защищённая зависимость;
- заполненные лимиты и большие тела, если применимо;
- ошибка записи или потеря связи, если применимо.

### 5. Реальный UI

- Для connected UI есть хотя бы один браузерный прогон настоящей страницы.
- Проверяются роль, viewport, пустое и заполненное состояние.
- Regex исходника и `innerHTML` unit-тест не заменяют браузерный путь.
- Если браузер недоступен, статус не выше connected и причина записана явно.

### 6. Проверка области изменений

- Diff сопоставлен с разрешёнными файлами.
- Generated-файлы обновляет только объявленный владелец.
- Legacy 0.9 не используется как доказательство правила LionWing.
- В отчёте перечислены неподключённые API, предложенные patches и `not-run`.

## Минимальный отчёт интегратора

Для каждого блока записать:

1. статус: foundation / connected / verified / blocked;
2. production entry point;
3. единственный writer;
4. реальные зависимости, использованные тестом;
5. сохранение и сетевой путь;
6. браузерный сценарий;
7. известный остаток;
8. SHA, на котором выполнен полный `npm test`.

Merge разрешён для foundation, только если он не загружается runtime и явно
помечен как foundation. Пользовательская готовность повышается только для verified.
