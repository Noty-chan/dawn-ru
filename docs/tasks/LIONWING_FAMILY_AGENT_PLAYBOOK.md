# LionWing: экономная реализация десяти семейств

## Решение пользователя, 2026-09-06

Следующая задача — рабочая база десяти семейств, затем адаптеры и уточнение базы
по реальным потребителям. Полный аудит всех 333 Уровней не блокирует разработку.
Буквальный разбор требований можно поручать Sol; ограниченные задачи по контрактам,
документации и локальным изменениям — Terra. Старший агент проверяет результат.
Часть Даров остаётся на английском: отдельная очередь локализации.

Работа в `codex/lionwing-rules-kernel`. Выпуск стола в main был отдельным поручением:
новую разработку семейств не публиковать в main автоматически. Значимый законченный
блок — отдельный коммит после проверок. `source/supplements/` и посторонний
`site/dead-gods/maps/` не менять.

## Как уменьшать стоимость

1. Один первоначальный аудит соответствия существующего кода требованиям.
   Повторно используем старые чистые запросы только после проверки изоляции редакций.
2. Один исполнитель владеет изменениями runtime на время блока. Параллельно другой
   агент может готовить контракт следующего блока в отдельном документе.
3. Агент получает точные входы, результат, разрешённые файлы и критерии приёмки.
   Не пересказывать ему всю историю разговора; передавать этот файл и нужные документы.
4. Короткий отчёт: что работает, какие проверки прошли, что осталось, хеш коммита.
   Не выводить целиком сгенерированные каталоги и длинные журналы успешных тестов.
5. Старший агент проверяет diff и опасные границы: чужой персонаж, позднее изменение
   состояния, повтор команды, вложенный выбор, отмена, сохранение и публичная проекция.
   Повторные исследования и тесты нужны только при конкретной причине.

## Общие обязательства исполнителя

Прочитать ближайшие CODEX.md. Использовать существующие `lionwing.command`, prepare,
dispatch, preview и UI-адаптер. Сцена содержит JSON, а не функции. ID правила,
действия, цели, причины и экземпляра последствия не зависят от отображаемых имён.
Игрок отправляет намерение или ID выбора; авторитетный обработчик проверяет владение,
версию, условия и разрешённые параметры. Закрытые планы не раскрываются игрокам.

Не добавлять механизмы только ради декларации семейства. У каждой новой возможности
есть реальный потребитель из ручного реестра или точный обезличенный сценарий,
доступная операция на столе и проверяемый результат. Готовый API без пользовательского
пути помечать как промежуточный, не как готовое семейство.

Сначала сохраняемые общий контракт и операции, потом тонкие адаптеры. Не переносить
статусы автоматизации старой редакции в LionWing. Неоднозначность канона фиксировать
отдельно; сохранять ручное решение Нарратора вместо придуманной автоматизации.

## Последовательность блоков

| Блок | Семейства | Результат |
| --- | --- | --- |
| 1 | execution, history, costs, health, dice | Причинность и сохраняемые решения, фактическая история и лимиты, составная цена, различие урона/потери/расхода ЗД, проверяемые броски |
| 2 | geometry, effects | Геометрический источник отдельно от владельца, движение по сегментам, занятость тела, источники/подавление/неснимаемость и вычисляемые ауры |
| 3 | actions, turns | План до оплаты, конфликты модификаторов, действия вне Хода, сохраняемое прерывание и возобновление без повторных сбросов |
| 4 | entities | Жизненный цикл принадлежащих сущностей, связи, пилотирование, движение и очистка с учётом предыдущих контрактов |
| 5 | интеграция | Различающиеся композиции семейств, браузер, сохранение/откат и сериализованные сетевые намерения |

Семейства не обязаны соответствовать отдельным файлам. Порядок уточняется по реальным
зависимостям; например аура может требовать минимального идентификатора сущности
раньше полного блока entities. Не создавать циклические вызовы редьюсеров.

## Приёмка каждого блока

- Успешная операция и недопустимая цель/состояние.
- Отмена до оплаты и атомарный отказ составной цены.
- Повтор ID, конфликт версии и поддельное намерение игрока.
- Вложенное решение или Реакция, если применимо; сериализация и продолжение.
- Журнал различает исходное намерение и фактический результат.
- Откат возвращает последствия, историю и использованные лимиты.
- Кнопка/форма на столе, понятные цель, цена, причина отказа и отмена выбора.
- Старые игры проходят прежние тесты; `npm --prefix apps/companion test` успешен.

`implementationStatus` повышать только для доказанного объёма. В отчёте сопоставлять
каждый пункт `lionwing-rule-families.json` с кодом и проверкой; оставшиеся пункты
указывать явно. «Фундамент реализован» не означает «все 333 Уровня автоматизированы».

## Шаблон задания следующему агенту

> Продолжи блок N по этому файлу и контракту предшествующего блока. Сначала проверь
> HEAD и рабочее дерево. Изучи существующие реализации названных операций и ручные
> требования их потребителей. Реализуй общий контракт, сериализацию, пользовательский
> путь и сценарные тесты. Не делай массовый аудит или адаптеры других Уровней.
> Не трогай файлы другого исполнителя, main и production SQL. После успешных проверок
> сделай отдельный коммит. Передай хеш, краткую карту требований и конкретные пробелы.
