# Передача работ: LionWing RU/EN

Дата среза: 4 сентября 2026. Рабочая ветка: `main`.

Этот файл — точка входа для продолжения миграции с другого устройства или
аккаунта. Перед началом выполнить `git pull --ff-only origin main` и проверить
`git status --short`. Локальная папка `source/supplements/` содержит закрытые
материалы и не должна попадать в Git.

  LionWing использует отдельный английский канон.
- Канон LionWing хранится структурированно в
  `source/editions/dawn-en-lionwing-cb2f8e67/canonical/` и собирается в
  `apps/companion/edition-lionwing.js`.
- Русский LionWing хранится отдельным overlay в
  `apps/companion/edition-lionwing-ru.js`; английский канон ради перевода не
  изменяется.
- Переведены и подключены все 111 Техник LionWing: 106 изменённых и 5 новых.
- Переведены 10 Мировоззрений и 54 изменённых или новых Дара: 33 + 21.
- Для всех 104 актуальных слов Способности есть русский текст. В него входят 35
  новых слов; 14 удалённых слов 0.9 не протекают в LionWing.
- Билдер получает стартовые ранги, прирост рангов, минимум Навыков, стартовые
  Атрибуты, предел роста Атрибута и предел Мировоззрений из правил выбранной
  редакции, а не из неявных констант 0.9.
- JSON героя сохраняет и восстанавливает редакцию, язык и список дополнений.
- LionWing допускается на игровой стол в ручном режиме. Автоматизация Техник 0.9
  к нему не применяется.
- Реестр дополнений отделён от основных редакций. Платные PDF и полные закрытые
  тексты в публичную сборку не входят.

## Архитектурные запреты

1. Не переносить новые правила в `apps/companion/data.js`: это канон русской 0.9.
2. Не исправлять 0.9 «по смыслу» данными LionWing. Изменение редакции должно быть
   явным через `rulesEdition`.
3. Не переводить поверх `edition-lionwing.js`. Русские значения добавляются по
   стабильным ID только в `edition-lionwing-ru.js`.
4. Не подменять изменённый английский текст старым русским переводом без сверки.
5. Не менять стабильный ID из-за нового английского или русского названия.
6. Не включать автоматику 0.9 для героя LionWing. Пока правило не портировано,
   его разрешает Нарратор вручную.
7. Не добавлять `source/supplements/`, исходные платные PDF и извлечённые полные
   книги в коммит или Pages.

## Следующие крупные шаги

### 1. Закончить перевод системы LionWing вне стола

- закрыть необязательные вопросы предыстории и рецепты сборок со страниц 24–31,
  затем продолжить профили NPC и Модификаторы со страниц 125–130, не затрагивая
  интерфейс стола;
- перевести этот слой по актуальному английскому источнику, не копируя изменённый
  текст из русской 0.9;
- подключать механику по стабильным ID и `rulesEdition`, не изменяя данные 0.9;
- проверить формулы Способности, импорт/экспорт и неизменность ID и бюджетов при
  переключении RU/EN.

### 2. Довести справочник и редакторскую сверку

- локализовать оставшиеся общие строки инструментов и короткие тексты создания;
- не переносить в справочник большие главы книги: им место в будущих Правилах;
- добавить заметный статус английского fallback для ещё не вычитанных блоков;
- пройти `TRANSLATION-REVIEW-RU.md`, сохраняя согласованные названия
  «Предвидящий», «Небесный святой», «Хрономант», «Заклинатель талисманов» и
  «Ангел-хранитель», если новый канон не требует отдельного редакторского решения.

### 3. Граница текущего потока

- интерфейс, игровой стол и Пульт Нарратора ведёт отдельный исполнитель;
- в этом потоке не менять их поведение и разметку;
- изменения данных и системной логики обязаны сохранять существующие тесты стола;
- после завершения ручной системной основы автоматизацию LionWing переносить
  небольшими типизированными группами правил.

Автоматизацию нельзя строить на распознавании английского или русского текста.

## Быстрая проверка

```powershell
cd apps/companion
npm test
```

Для браузерной проверки можно открыть `apps/companion/index.html` напрямую или
запустить локальный HTTP-сервер. Минимальный smoke-тест: создать героя в RU
LionWing, переключить интерфейс в EN, экспортировать его, импортировать обратно и
открыть справочник и стол в ручном режиме.

Перед коммитом:

```powershell
git diff --check
git status --short
```

Добавлять в индекс только перечисленные рабочие файлы. Если в статусе остаётся
`?? source/supplements/`, это ожидаемо: папку следует оставить локальной.
