# Модификаторы LionWing — аудит перед переносом

Источник правил: `source/original/DAWN_ The RPG (LionWing Edition) w Bookmarks.pdf`, PDF-страницы 125–127 (печатные 124–126); canonical EN: `source/editions/dawn-en-lionwing-cb2f8e67/canonical/core-rules.json`. Этот контур отделён от 41 обычного NPC и 122 их Action/Attack/Ace.

## Фактическое состояние

- LionWing содержит **12** профилей: Artillery, Blaze, Collateral, Contagion, Earthquake, Gargantuan, Giant, Haven, Isolation, Legion, VIP, Vortex. Их стабильные ID — `lionwing.modifier.*`.
- `scene-modifiers.js` описывает **11** профилей `enemy.modifier.*` прежней редакции; Blaze отсутствует. Формулы и механика отдельных одноимённых профилей в LionWing изменились, так что переименование ID не является реализацией.
- `lionwing-table-data.js:profiles` возвращает только `coreRules.npcs.list`, а `scene-ui.js:allEnemyProfiles` использует этот список для выбора на LionWing-сцене. Канонические модификаторы сейчас не представлены в этой форме.
- `tests/enemy-modifiers.mjs` создаёт сцены без `rulesEdition: "lionwing"` и проверяет существующий legacy writer. Зелёный тест не удостоверяет применение модификатора в LionWing.
- `lionwing-engine.js` маршрутизирует сцены LionWing в собственный `dispatchMany`; старые `scene-modifiers.js`-триггеры нельзя считать подключёнными только по наличию общего `DAWN_SCENE_ENGINE` API.
- Отдельный read-only аудит и моя сверка кода показали три конкретных несовпадения: legacy Isolation считает базу `6(+1)` вместо LionWing `2 + Tier`; legacy Vortex привязывает цель и получение Брони к отмеченному игроку вместо NPC Host; legacy Vortex создаёт 4 Зоны вместо канонических 5. См. `scene-modifiers.js:338`, `:376`, `:419`, `:503` и PDF-страницу 127. Эти отличия подтверждают необходимость маршрута по редакции.

## Канонический контракт

NPC-модификатор прикрепляется к уже развёрнутому NPC, передаёт ему показатели и пассив. По одному показателю выбирается наибольшая прибавка среди модификаторов; прибавки к разным показателям сочетаются. Модификатор Сцены действует либо вместе со Сценой, пока живы враги, либо хранится во враге и действует, пока тот на поле. Оба вида не являются целями и не получают Ход.

| Семейство | Профили | Основной контракт реализации |
| --- | --- | --- |
| NPC attach, числовые прибавки | Blaze, Contagion, Earthquake, Gargantuan, Giant, Vortex | Владение Host, максимум прибавки по стату, source loss, совместная проверка диапазона и тела |
| NPC attach, атака/триггер | Blaze, Gargantuan, Giant, Vortex | Криты Primary Attack, новая атака Host, геометрия, Round boundary |
| Scene area и переназначение | Artillery, Haven, Isolation | Форма/цель, конец Раунда, новый выбор, alongside/stored режим |
| Scene stakes и сущности | Collateral, Legion, VIP | Развёртывание, защита целей, часы, поражение, возврат, сопровождение |

## Миграция сохранений

Пользователь выбрал автоматический перевод старых `enemy.modifier.*` в LionWing-сценах. Миграция должна учитывать тип сцены и не менять 0.9. После смены ID нельзя молча сохранять старые числовые бонусы и уже разыгранные эффекты как канонические: состояние размещения и прикрепления следует сохранить, а производные показатели пересчитать по LionWing. Для сцены в середине Раунда понадобится отдельная проверка повторного срабатывания.

## Открытая формулировка источника

Isolation назван `Scene Modifier; Deploy alongside the Scene`, однако его Passive начинается `When this is Attached`. Пользователь уточнил трактовку для стола: при подготовке боя **прикрепить Изоляцию к одному врагу-носителю**, затем указать персонажа игрока как центр эффекта. Пассив действует, пока носитель находится на поле; после каждого Round-end нужно указать другого игрока. Это явное решение пользователя при конфликте строк PDF, а не буквальная формулировка заголовка профиля. Общий закон `Always Round Up` на PDF-странице 35 округляет вверх частный урона между получателями: например, при Tier 2 и четырёх игроках общий урон 16, разделённый между тремя получателями, даёт 6 каждому.
