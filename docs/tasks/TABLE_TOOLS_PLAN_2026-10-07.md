## Обсуждение

Три агента одного уровня: `player_advocate` — адвокат пользователя,
`gameplay_rules` — проверка правил и игрового цикла,
`tools_network_design` — инженер инструментов, сети и проверок.
Они обменялись замечаниями напрямую; root проверил код и текущий браузер.

Критика изменила первоначальные предложения:

- Прозрачный фон при сохранении отдельной колонки не освобождает поле.
  Нужна действительно плавающая палитра.
- Ссылка на редактор вместо основного действия не считается инструментом.
  Группы оправданы выбором типа/формы, а не ещё одним переходом в меню.
- Новые нейтральные инструменты нельзя добавить в `changeSceneTool()`:
  он отменяет подготовленные действия. Показ и измерение имеют отдельное локальное состояние.
- `erase` удаляет также персонажей. Для окружения нужен ограниченный ластик.
- Нынешнее название «Ручной» не выключает LionWing; `placement:true`
  также запускает игровые последствия. Скрытия кнопок недостаточно.
- Замена режима на старый `scene-reset` отклонена: он лечит и удаляет данные.
  Возвращение к правилам требует новой явной команды начала боя.
- Хеш цвета допускает совпадения, сортировка участников перекрашивает их.
  Для устойчивого различения пяти игроков нужен назначаемый слот.
- Общий broadcast не подтверждает личность автора; `senderId` из пакета недоверенный.

## Игровые циклы

**Игрок, с правилами:** выбрать свой токен → прочитать/открыть приём → измерить
или показать намерение → выбрать цель/клетку → подтвердить действие → увидеть итог.
Измерение, чтение и пинг не тратят ресурсы и не отменяют подготовку.

**Ведущий:** выбрать участника → прочитать профиль/приёмы → объявить или разрешить
исход → изменить нужные ресурсы → передать ход. Окружение и метки редактируются
непосредственно на поле; подробные настройки открываются по необходимости.

**Ручной стол:** выбрать/переместить токен → измерить/показать → бросить кубики
и договориться об исходе → явно записать здоровье/ресурс/пометку → отметить,
кто играет. Не возникает оплаты, Реакции или пассивного эффекта без решения человека.

Основная палитра: прямые **Выбор, Линейка, Пинг**; функциональные группы
**Показать** (линия/клетки/прямоугольник), **Окружение** (местность/стена/ластик),
**Метки**, **История**. Категории «Стены», «Топология», «Обзор» отдельно не нужны.
Открытие группы не активирует молча опасный инструмент.

## Подтверждённые причины

- `app-scene-events.js:186` вычисляет число линейки; `scene-ui.js` выводит его
  только в `#scene-selection-summary`, который скрыт вместе с `.scene-tool-actions`.
  Браузер: A1 → D2, текст «4 кл.», пять помеченных клеток, высота текста 0.
- Hover в `app-scene-events.js:241` использует `Scene.tool`; инструмент игрока
  находится в `playerSceneTool`. VM воспроизведение: player measure + GM select
  не даёт preview, GM measure даёт.
- `scene-board-tools.js` переносит параметры в `#scene-map-tools`, а выбор
  area/wall/marker/topology в обработчике открывает панель карты.
- В wheel-handler debounce стоит перед `preventDefault`. Реальный handler:
  из пяти событий стены три допускают обычную прокрутку.
- HUD ограничивает координаты краями, но не проверяет пересечение с токеном.
  Реальный harness: поле x300–550, токен x350–500 шириной 150 → четыре
  кнопки заходят на токен на 2 px. Проверка маленького токена этого не обнаруживала.
- Новая оболочка сохраняет фоновую колонку инструментов 108 px; media/map
  получают один `view`; нижняя панель переносит строки и содержит `margin-left:auto`.
- `sceneControlMode` локален и не передаётся в dispatch LionWing. При этом
  `applyContentPreferences()` принудительно ставит старый `manual` для LionWing.
  Этот флаг нельзя мигрировать в настоящий ручной режим.
- VM ядра при старом manual: turn-start Focus 10→2, ОД 0→3;
  turn-end с Regen ЗД 5→10; placement через enemy Gas создаёт actor.enter,
  effect.apply и consequence.completed.

## Настоящий ручной стол

Одна Scene, те же персонажи/объекты, сеть, права, журнал и базовые data reducers.
Новая **общая политика стола** отличается от локальной настройки внешнего вида.
Игрок не меняет её; авторитетная сторона проверяет её до исполнения команды.

Остаются: свободное перемещение своих токенов, карта и инструменты, описания,
обычные кубики/арифметика выбранного пула, явные числовые правки и пометки,
необязательный общий указатель текущего участника и ручной счётчик раунда.
Личный выбор для чтения профиля не меняет общего указателя.

Убираются: кнопки автоматизированных действий/Техник/Реакций, предложение исхода,
цены/автоматическое списание, поиск очередной реакции и автоматические пассивы.
Права, числовая валидация и целостность ссылок продолжают работать.

Отдельный allowlist table-команд использует общие примитивы хранения,
но не вызывает движение/вход/ауры/последствия/границы Хода/Разрушение.
Существующие `move(placement:true)`, `correct` и `prepareDestroy` не считать
готовым безопасным ручным API: во всех обнаружены дополнительные игровые последствия.

**M01:** перемещение через Gas/ауру/Snare меняет только позицию и технический trace;
ОД, ЗД, эффекты, последствия и ожидаемые выборы идентичны.
**M02:** смена ручного указателя и +3 ручных раунда не меняют core round/serial/activeTurn,
Focus/AP/HP/expiry и не запускают границы. Общие display-поля живут в той же Scene.
**M03:** явная правка HP=0 не назначает Рану/KO/Напряжение; Snare-пометка не двигает;
maxHp ниже HP отклоняется либо запрашивается явная правка обоих полей.
**M04:** удаление объекта чистит технические ссылки, без Damage/KO/stat refund/expiry/choice;
отмена возвращает данные и ссылки.
**M05:** первоначальное создание из листа/профиля заполняет базовые значения один раз;
чтение, render, reload и обновление описания не перетирают ручные ресурсы/позиции/пометки.
Deployment-пассивы NPC не срабатывают при ручной постановке.
**M06:** старые автоматические кнопки, горячие клавиши, API/очередные команды не исполняются
в manual, даже если старая вкладка не обновлена. Проверить на двух клиентах, не только UI.

Режим выбирается при подготовке. MVP не обещает возобновление замороженного боя
после произвольных ручных изменений. Переход manual→rules — новая явная команда
«Начать бой по правилам» с выбором первого участника и кратким показом изменений.
Она атомарно меняет policy и инициализирует Round 1, Tension 0, стартовый Focus,
ОД по каноническим исключениям. Карта, позиции, здоровье, раны, стресс, влияние
и ручные пометки сохраняются. Не использовать `#new-scene`/старый reset.
Старые автоматические сроки/источники требуют явного перечисления в договоре старта;
не применять догоняющие события. Незавершённые действия блокируют переход.
Отмена показа изменений оставляет всю Scene прежней. Мастер настройки не нужен.

## Временный сетевой показ

Законченный жест отправляется один раз; pointermove даёт только локальный preview.
Линия/прямоугольник — конечные клетки, список клеток ≤128, пакет ≤2 KiB.
Пинг живёт 1,2 с, рисунок 6 с; на автора одна демонстрация и один пинг.
Дубликат ID не продлевает срок. Ограничение 3 жеста/с с burst 4 с обеих сторон.
Рисунки не меняют Scene/version, не входят в intent queues/undo/snapshot/DB.
SVG не перехватывает мышь. Место задаётся клетками и spaceId, не экранными пикселями.

Повторно использовать lifecycle/auth/reconnect/generation guards `sync.js`,
добавить отдельный overlay и временный транспорт. Не рассылать восстановленные жесты.
Очистка при logout/leave/смене комнаты/новом публичном epoch; показывать только
соответствующее пространство. Hidden actor/profile IDs и содержимое GM-объектов запрещены.
`lwGeometrySceneIdentity` не подходит: включает скрытые actor IDs.

Автор — аутентифицированный участник, независимо от выбранного героя.
Предложение: private topic на отправителя, чтение — участникам этой комнаты,
отправка — только владельцу topic по auth.uid(). Личность берётся из доверенной
подписки, не из senderId/цвета пакета. Слот цвета назначается сервером однократно
при вступлении; пять игроков получают разные устойчивые цвета и имена на рисунках.
Ручные жесты не создают DB-записи; назначение слота — отдельная операция вступления.

RLS/private channel опираются на [Realtime Authorization](https://supabase.com/docs/guides/realtime/authorization).
Private/public каналы изолированы согласно [Realtime Concepts](https://supabase.com/docs/guides/realtime/concepts);
глобальную настройку публичных каналов не менять, существующие сигналы сцены сохранить.
Нет public fallback, объявляемого безопасным. Не включать до проверки реального RLS.
Расчёт 5 подписок/клиент =25/игру =125/пять игр не доказывает лимит production-проекта.
