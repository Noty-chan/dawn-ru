# LionWing: карта будущей автоматизации / Future automation map

Эта карта отделяет безопасное повторное использование старого стола от механик LionWing, которые нельзя честно получить простой заменой текста или профиля. Автоматизация начинается только после совместного ручного аудита.

This map separates safe reuse of the old table from LionWing mechanics that cannot be implemented honestly by replacing labels or profiles. Automation starts only after the collaborative manual audit.

## Что можно сохранить / Safe to reuse

- модель Сцены, клетки, токены, несколько пространств и ручное перемещение;
- прямые изменения Здоровья, Фокуса, ОД, Ран, Стресса, Влияния и Напряжения;
- журнал с откатом последнего изменения;
- области, Стены, маркеры и универсальные часы;
- импорт/экспорт переносимого JSON и стабильные ID;
- сетевой обмен состоянием после проверки схемы редакции.

- Scene state, grid, tokens, multiple spaces, and manual movement;
- direct edits to Health, Focus, AP, Wounds, Stress, Influence, and Tension;
- log plus single-step undo;
- areas, Walls, markers, and generic Clocks;
- portable JSON import/export and stable IDs;
- network state synchronization once the edition schema is validated.

## Приоритет после ручного теста / Priority after manual testing

1. **P0 — ручная выразимость:** движение, точные ресурсы, повтор N раз, массовый выбор целей, часы и сроки.
2. **P1 — прозрачные ограничения:** AP, одна цель, одно действие, пороги Козырей, начало/конец фаз.
3. **P2 — сложные сущности:** Fodder, Summons, Compound NPCs, Modifiers и Antagonist Edges.
4. **P3 — автоматическое разрешение:** броски, награды, реакции и полные цепочки Техник только после подтверждения P0–P2 за реальным столом.

1. **P0 — manual expressiveness:** movement, exact resources, repeat N times, multi-target edits, Clocks, and expiry.
2. **P1 — visible constraints:** AP, per-target and per-action limits, Ace thresholds, phase boundaries.
3. **P2 — complex entities:** Fodder, Summons, Compound NPCs, Modifiers, and Antagonist Edges.
4. **P3 — automated resolution:** rolls, rewards, reactions, and complete Technique chains only after P0–P2 survive real table use.

## Принцип миграции / Migration principle

Старый вариант не выбрасывается: он остаётся проверенным UI и хранилищем состояния. Но его автоматические обработчики нельзя считать правилами LionWing. Новый движок должен получать `editionId`, работать по стабильным ID и объявлять поддерживаемую возможность для каждого действия. Если возможности нет, карточка остаётся читаемой и стол предоставляет прямые ручные изменения.

The old implementation is not discarded: it remains a proven UI and state store. Its automated handlers must not be treated as LionWing rules. The new engine must receive `editionId`, operate on stable IDs, and declare support per action. Unsupported actions remain readable while the table exposes direct manual edits.
