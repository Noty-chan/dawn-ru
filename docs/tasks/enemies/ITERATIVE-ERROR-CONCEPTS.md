# Concepts from iterative LionWing enemy review

These are reusable failure patterns to check before calling a new adapter fully automated. Each came from a concrete review finding; the examples are brief so they can guide later reviews without becoming a second implementation spec.

## Standing review directive

When a check or fix reveals a defect, repair the shared cause where possible, test at least one sibling use, and record the general failure pattern here. Delegate the wider search across other consumers to Luna reviewers; they return concrete, reproducible cases and do not edit production code. The integrator accepts or rejects those findings, fixes confirmed cases, and records what remains unverified. This keeps broad checking continuous without making every local fix wait for a full manual audit.

1. **One rule, one calculation owner.** Marked damage was added in the Attack preview and again in a proposed resolution patch. A modifier belongs at the phase named by its trigger. Check the actual committed result with different attacker/defender Tiers and with Armor/Evasion, not just the preview number.
2. **A prepared event is a request, not proof.** S01 originally validated a valid-looking Prepare while allowing unrelated events in the same batch. Validate the exact event sequence, count, actor, payload and current scene before the shared writer mutates state.
3. **Replay has two identities.** Reusing old event IDs should be idempotent; regenerating IDs for the same once-per-Round Action must still be rejected by game state. Test both cases.
4. **Availability and commit must agree.** UI availability and target selection can be stale after a reaction, knockout, suppression, disappearance, or pending chain. Recompute targets and effective effects at commit; never rely on raw `actor.effects` when suppression or auras matter.
5. **Check the exact source wording and every target category.** “Any character” includes allies and self. A convenient enemy-only or non-self filter silently changes the rule. Verify unusual targets explicitly.
6. **Movement type matters.** Ranger Aim is lost on ordinary movement in its own Turn, not on forced movement, teleportation, or placement. Record the cause of movement and test each route.
7. **Damage bonuses cannot create their own trigger.** Marked requires an Attack that already deals damage; Evasion reducing damage to zero must preserve Mark. Apply the bonus after defenses and only once per Attack.
8. **A prompt must reach its real writer.** Ranger had a valid-looking prompt, but `rule.respond` did not route through the enemy continuation path. Exercise the UI action through response and final commit, not only prompt creation.
9. **Saving must preserve every accepted source.** The effect writer could accept 13 independent sources while save normalization kept 12; the legacy writer kept a different 12. Preserve accepted sources and reject overflow atomically at the writer rather than silently changing game state on reload.
10. **Deferred work must survive persistence.** The prompt reducer accepted 29 queued decisions while save normalization kept 24, leaving audit entries for prompts that would never appear. Queue limits belong at the producer; save normalization must retain accepted work.
11. **An attack event is not proof of a paid action.** A bare `attack.pending` at the LionWing reducer boundary opened a hero attack even with no AP and an already-used action. Bind ordinary attacks to one prepared action instance and reject replay; keep explicit Narrator and triggered-reaction paths distinct. When adding another event producer, test a forged standalone event as well as the normal action flow.
12. **A zero-target action can still be valid.** Viper's Lick The Knife has an AP cost even when no eligible Blighted player exists. The commit validator must accept the exact canonical prepare/spend/resolve batch with no damage events, while rejecting forged damage or omitted payments.
13. **Storage cleanup must cover every media owner.** Moving Scene and preset art to IndexedDB prevents quota failures, but deleting the visible art must also release its stored payload. Track live references for heroes, Scene art and presets together; test removal and persistence.
14. **A painted zone is not a target selection.** Deployment brushes must create visible areas without changing the attack target set. Check the interaction on cells already occupied by a token and across every loaded table stylesheet; later styles can hide correct state.
15. **Special objects need a round-trip contract.** A valid in-memory Corpse marker was normalized to an ordinary Mark because the save whitelist did not include `corpse`. Check every producer's kind and provenance fields against scene normalization and library normalization, then test save/load before claiming a rule complete. The same review also found top-level marker attachment and source-loss fields were omitted even though reducers produced them.
16. **Relink or refuse copied rule objects.** A saved special Fodder Zone cannot reuse its old owner or target ID when deployed as reinforcement. Map IDs only to known live actors of the right team and field; if an owner, target, or required geometry is missing, skip the zone with a Narrator message. Do not leave a failed placement's cell reserved for the next actor.
17. **A network tick has one version equation.** The persisted scene version must equal the expected version plus the number of events in the batch. Derive that number at the final network boundary and reject deterministic mismatches without retry loops; retry only genuine concurrent scene-version conflicts. Verify deployment with the same event route as other player actions.
18. **A legal Prepare is not evidence of payment or availability.** The Corpse Fodder writer accepted a canonical `enemy.action.prepare` followed by `actor.spawn` with no AP spend; Danse could disguise its Ace as an ordinary Action and bypass Tension or scene-use limits. At the event boundary, match the canonical rule kind, current availability and exact resource-spend receipt before accepting a derived spawn or conversion. Test a partial packet and forged kind, not only a full plan returned by `prepareEnemyRule`.
19. **Generated IDs must be checked against live entities.** Army Of Stone derived Fodder IDs from its action token, while Swarm/Bodyguards Deployment derived them from the owner ID. Either could generate an ID already used by an actor. Validate every derived ID against the current scene before removing Terrain, spending the action, or adding the deployment; test the collision as an atomic rejection. Apply the same check to other event-generated entities during wider review.
20. **An off-board rule owner must be absent from every spatial query.** Swarm and Bodyguards retain an actor to own Turns and Actions while their deployed Fodder occupies the board. Hiding that actor in the UI and rejecting direct targeting is insufficient: generic area queries can bypass target checks, and presence checks can still count the invisible anchor as a figure. Exclude deployment proxies from default actor queries and mark them off-field; keep their profile Actions available.
21. **A lifecycle trigger needs the committed event route.** The LionWing kernel updated a Fodder Zone's health without running the legacy scene trigger that clears Bodyguards Brace or checks the Deployment passive. Connect the specific committed boundary to its follow-ups, avoiding a broad reroute of unrelated damage. Test actual KO, direct KO, movement, persistence, and forged events. Trigger only on boundary types that can justify the resulting state change.
22. **Crowd placement has its own occupancy rule.** Swarm/Bodyguards Deployment initially counted every character as occupying a cell and reported insufficient room on a board that had enough distinct cells. Fodder may share a cell with a character; only another living Fodder Zone prevents placement. Prefer empty cells for readability, then use legal shared cells before falling back to manual deployment. Test a board filled with characters but not Fodder.
23. **An explicit deployment area is a boundary, not a preference.** A passive placement routine prioritized marked deployment cells but continued outside the marked area if it needed more space. If a side has an explicit area, either fit every generated Zone inside it or reject the placement with a clear reason; do not silently break the Narrator's placement rule. Test both a too-small zone and an exact-fit zone.
24. **Accepted state must survive normalization.** The Scene writer accepted more than 30 clocks, but save and network normalization kept only 30. Never silently truncate an accepted collection during persistence; replay a boundary-sized state through the actual normalizer.
25. **Generated entities need collision checks before mutation.** Collateral derived clone IDs from its owner and index without checking existing actors. Validate every resulting ID before placement; a legal cell does not guarantee a unique entity identity.
26. **Canonical action identity includes its type, availability, and payment.** A Revenant Ace could be relabeled as an Action, and an enemy Attack could be submitted without Prepare or AP. At the authoritative writer, resolve the rule from its owning profile and require its true kind, current availability, and a matching paid receipt before accepting the Attack. Test forged partial packets as well as normal plans.
27. **Spatial query and typed target policy must agree for hidden entities.** An attached hidden modifier was rejected by typed targeting but selected by generic area queries. Hide the modifier from default spatial queries while retaining explicit opt-in for internal inspection. Test both the carrier and the modifier in one cell.
28. **Canonical profile IDs must reach their passive lifecycle.** Legacy Revenant suppression of KO Tension and Round return matched only the legacy profile ID; the LionWing kernel had its own KO meter path. Check the actual kernel route and canonical ID before declaring a copied passive automated.

For future slices, pair one normal scenario with a forged event, a stale scene, a replay with fresh IDs, and a boundary case that changes the outcome. Record unresolved cases before raising automation coverage.

## Shared acceptance gate for new enemy attacks

Canonical LionWing NPC `attack.pending` events are now re-prepared from the pre-commit Scene and compared with the submitted attack payload. The gate requires the profile's rule ID, a matching Prepare and AP spend, and the same targets, geometry, roll, damage, effects and follow-ups that the canonical planner would produce. Do not bypass this gate for a new automated NPC Attack. If a new action needs another choice (movement, area anchor, or similar), make that choice reconstructible from the submitted event sequence and add an adversarial test before marking it automated.

For each new attack family, test a valid package and mutations of at least its AP cost, range or area, target list, dice faces or success count, damage, effects, a missing rule ID, and replay with existing event IDs. This is a focused family test; the shared gate avoids copying these checks into every profile adapter. Hero actions, manual Narrator commands, and non-Attack enemy actions have separate entry points and still need their own authority review.
