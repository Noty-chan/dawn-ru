# LionWing: первые сквозные адаптеры, 2026-09-06

## Что работает

`lionwing-execution.js` — чистый контракт сохраняемого последствия: исходная
операция, владелец решения, идентификаторы причины и исходного действия,
варианты замены, фазы before/apply/replace/after. Он возвращает план, состояние
меняет только `lionwing-engine.js`. Выбор одной замены исключает исходное
наложение; завершение замены не выдаётся за применение исходного Эффекта.

Первые потребители — все пути получения Эффекта в LionWing, включая Эффекты
ручной Атаки и базовых действий. Очередь останавливается до применения,
обрабатывает Эффекты по одному, сохраняет остаток пакета и вложенные решения.
В публичном выборе только ID и подписи; исполняемый план остаётся в закрытом
продолжении Нарратора. Игрок отправляет выбор, авторитетная сторона исполняет
сохранённый план. Подмена операций в намерении не допускается.

`lionwing-adapters.js` подключает **Berserker II / Загнанный пёс**: получить
2 урона вместо положительного или отрицательного Эффекта. Урон проходит обычное
ядро, включая Уклонение, Рану и Сопротивление. Это добровольно полученный урон
самому себе; он не становится Атакой исходного источника Эффекта.

Нарратор включает адаптер в Пульте → Ход → Автоматизация Техник у героя,
изучившего Берсерка II или III. Читается `knownTechniques`, который хранит
изученные Техники LionWing; старый список автоматических обработчиков остаётся
отключённым. По умолчанию адаптер выключен, чтобы не дублировать ручное исполнение
в существующих сохранениях. Уровни I и III по-прежнему разыгрываются вручную.

## Проверки

- Автотест обезличенного выбора конкурирующих замен: порядок регистрации
  не выбирает победителя, исходный план не мутирует, повтор выбора запрещён.
- Digest адаптера сверяется с текущим источником Уровня.
- Реальный адаптер: принять Эффект / заменить, положительный Эффект, несколько
  Эффектов подряд, остаток пакета, Рана → Сопротивление, Уклонение, сохранение,
  восстановление снимка отката, вложенное ручное решение и повтор события.
- Сериализованные сетевые намерения: принадлежность героя, закрытый план,
  поддельные операции, реальная функция отправки из публичного интерфейса игрока.
- Браузер: герой из билдера с Берсерком II → включение → ручное наложение
  Ослаблен → выбор до применения → перезагрузка → замена, ЗД 16→14 → откат,
  ЗД 16 и восстановленный выбор → принять Эффект, ЗД 16 и Ослаблен.
  В этом сценарии ошибок консоли не было.

## Границы и следующий блок

Это первый узкий контракт исполнения, а не готовность всех десяти семейств.
Есть реестр afterEffect-срабатываний. Пока нет after-триггеров остальных операций, многоступенчатых замен замещающих
последствий, прерывания полного Хода и вычисляемых аур. Предохранительный лимит
одной транзакции не заменяет будущий учёт причин/лимитов всей цепочки.
Контракт конкурирующих замен проверен обезличенно; подключены два реальных адаптера.
Живая двухклиентная Supabase-сессия ещё не проверена.

Следующий блок: общий учёт фактического урона и лимитов каждого Хода плюс
сохраняемое окно действий вне Хода. Перед Berserker I/III сверить значение
бюджета ОД и точный порядок бесплатной Зарядки относительно Раны по оригиналу.
После этого — другая контрольная Техника для композиции модификаторов Атаки,
а не массовое подключение всех Уровней. Разбор оставшихся 300 Уровней продолжать
небольшими блоками одновременно с проверкой работающих потребителей.

Все 333 строки старой карты остаются с консервативной отметкой ручной проверки;
этот документ уточняет наличие двух экспериментальных адаптеров и не
объявляет всю Технику или её сочетания проверенными за столом.

## Второй потребитель: Самобичеватель I

После фактического получения отрицательного Эффекта общий обработчик получает
от адаптеров список необязательных планов. Каждый план имеет отдельный
сохраняемый выбор: выполнить или пропустить. Исполнение снова использует общие
операции, поэтому предлагаемое Усиление может быть заменено Берсерком II.
Пропуск after-правила не отменяет уже полученный отрицательный Эффект.

Проверено автоматическими сценариями и браузером: Помечен → принять →
Самобичеватель I → Усилить себя → Берсерк II предлагает заменить Усилен →
принять. В конце ЗД не изменились, оба Эффекта получены, очередь завершена.
Автотесты дополнительно проверяют отсутствие after-срабатывания после замены
исходного наложения, пропуск, вложенную замену Усиления на урон и общий rootActionId.

В реестр добавлены все три Уровня Самобичевателя с ручным разбором и отметкой
визуальной сверки PDF-страницы 69. Подробных черновиков теперь 33, ещё 300.
Неоднозначные II/III пока не автоматизированы. Бюджет Берсерка I по страницам
55/68 оригинала остался неоднозначен; автоматическая выдача ОД не добавлена.
