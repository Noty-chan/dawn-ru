## Первая итерация

1. **Отзывчивая линейка.** Обновлять только измеренные клетки, расстояние и
   подпись. Не перестраивать поле, пульт и подсветку правил. Не менять writer,
   AP, version, pending action или алгоритм геометрии.
2. **Устойчивый пульт.** Сохранить пользовательский ввод, focus/caret, раскрытия
   и прокрутку в пределах того же actor/scene/room/epoch/прав. Новые canonical
   ресурсы остаются актуальными. Смена контекста и потеря прав сбрасывают
   неподходящий draft. Repaint не отправляет native change как команду.
3. **Понятный компактный порядок.** Текущее решение/предпросмотр и базовые
   действия располагаются выше истории кубиков и инвентаря. Служебные секции
   закрыты по умолчанию и сохраняют явный выбор пользователя. Обязательные
   решения, подтверждение и отмена остаются видимыми. Новые подписи — RU/EN.
4. **Честное ожидание команды.** INSERT означает отправку, а не применение.
   Хранить правила-команды до terminal rejection либо applied и свежего
   canonical чтения в том же подключении. Старый snapshot/чужой version не
   является подтверждением. Не делать предварительное списание ресурсов.
   Защитить повтор того же actor до завершения; восстановление использует
   прежний envelope/clientIntentId, с ограниченными повторными чтениями.
5. **Разделить ID команды и сущности.** Узко исправить prepare fallback:
   item/clock ID не заменяет event identity. Два намеренных действия различны;
   точная повторная доставка одного действия по-прежнему идемпотентна.

Сначала обсуждение и этот план, затем реализация. Пункты 1–3 уменьшают работу
интерфейса и потерю контекста; пункты 4–5 защищают подтверждение и результат.

## Критерии приёмки

- Линейка в реальном браузере: неизменная идентичность DOM поля/пульта при
  движении между клетками, актуальная длина, сохранённый выбор Шага/его
  подсветка; Scene/version/AP не меняются. Снять p50/p95 отклика до/после на
  одинаковой локальной сцене. Не подменять время RPC временем локального paint.
- Пульт: ввод и caret переживают постороннее обновление; details/scroll
  удерживаются. Actor/room/epoch/role change не переносит прежнюю форму.
  Отмена и repaint ничего не оплачивают; актуальная цена проверяется снова.
- Rules pending: held INSERT, pending INSERT, старый snapshot, snapshot-before-ack,
  applied-before-snapshot, reject, повтор, потерянное уведомление, reconnect,
  поздний ответ прежнего подключения. Нет ложного synchronized, двойной оплаты,
  постоянного блока или потока лишних чтений.
- Identity: два расхода одного stack дают 3→2→1, точный replay не расходует ещё;
  два изменения часов различны; event-ID conflict и reload продолжают работать.
- Базовый бой через UI: manual preparation → cancel preview → start rules →
  AP/Focus → Шаг/атака и отмена → конец Хода/Раунд → сохранение/reload.
- Проверить EN/RU изменённый контур, клавиатуру, narrow viewport и reduced
  motion. Сетевой путь отдельно проверять двумя независимыми участниками,
  если доступен изолированный стенд/QA campaign. VM не выдавать за живую сеть;
  недоступную приёмку явно записать как not-run, без обещания production PASS.
- Целевые регрессии, полный npm test и git diff --check. Сгенерированные
  inventories обновлять только штатным генератором при изменении test evidence.

## Границы

В этой итерации не расширяется покрытие всех Техник, не переписывается ядро,
не добавляются новые камеры/геометрические кэши, не изменяются SQL, RLS,
Supabase config или пользовательские игровые столы. Боевые команды сохраняют
каноническое подтверждение, стоимость, отмену, журнал и единственного writer.
Legacy-дубли административных форм требуют отдельного обхода маршрутов;
массовое скрытие controls без доказательства доступности функций откладывается.

## Результат первой итерации — 12.10.2026

Статус: **implemented; verified в описанном объёме**. Все пять пунктов
реализованы; независимые ревью и полный `npm test` на `5130c4a` прошли.
Дополнительно исправлены проверка policy epoch до подготовки команды,
блокировки инвентаря и реакций при ожидании, а также Space на заголовках секций.

В одинаковых 7×7 сценах p95 локального обработчика линейки снизился с 236,3 до
3,2 мс, полные перерисовки при 24 наведениях — с 24 до 0. Базовый бой проверен
через UI. Два независимых клиента прошли приглашение, публикацию листа, запуск
rules, задержанное действие и reload через настоящую сеть; остальные ошибки
транспорта и механики покрыты отдельными DOM/VM стендами.

Браузерная приёмка использовала 127.0.0.1:8893 для baseline и 8894 для итогового
кода, новые профили и отдельную QA campaign. Эта campaign удалена после проверки;

сохраняются в ignored output/playwright. [Английский отчёт и границы проверки](RULES_TABLE_POLISH_QA_2026-10-12.md)
фиксируют точный тестовый commit, живые результаты и пропущенные проверки среды.
