# Ревью первой волны Luna: последствия, объекты Сцены, мобильный стол

Дата интеграции: 2026-09-21. База волны: `40cdc51`.

Этот документ фиксирует результат проверки L01–L03 после интеграции. Он важнее
самоотчётов агентов: здесь перечислены найденные интегратором ошибки, внесённые
исправления, фактически выполненные проверки и безопасная граница следующей волны.

## Итог

Все три блока приняты после правок интегратора. Общий `npm test` проходит. В
локальном Chromium проверены стол и панель «Объекты» при 390×844; ошибок консоли
нет, панель открывается и закрывается, заголовок, поиск и фильтры доступны. Это
не заменяет итоговую проверку заполненной Сцены, двух клиентов и опубликованного
сайта.

## L01 — постоянные последствия Уязвимости

Принято:

- пять стабильных категорий последствия;
- постоянная типизированная запись у героя, статус ручного применения и история;
- запрет повторной категории, сохранение после JSON reload и Scene reset;
- идемпотентность повторного события;
- совместимость со старым сохранённым окном `record`;
- read-only `consequenceStatus` для будущего UI.

Первоначальный результат нельзя было принимать без изменений. Новое окно также
предлагало `record`, поэтому игрок мог обойти одноразовость категорий свободной
заметкой. `lossTarget` принимал произвольный JSON. Тест обычного KO проверял поле
не в том месте, а тест «исправления Нарратора» фактически отправлял команду героя.

Исправлено:

- `record` разрешён только старому окну, где нет новых категорий;
- новые окна содержат только пять канонических категорий;
- цель потери обязана иметь ID и вид, согласованный с категорией; для двух Уровней
  Техник запрещено указывать иное число;
- тест проверяет глобальную очередь решений и попытки обхода;
- формулировка теста честно отделяет механику engine от проверки роли на UI/network
  boundary. Отдельный UI Нарратора остаётся задачей L04.

Остаток: UI выбора конкретного Навыка, части Способности, Дара или Техник; экспорт
героя; применение результата к билдеру только через preview/commit, без скрытой
правки листа.

## L02 — игровой список объектов Сцены

Принято:

- общий read-only список участников, массовки, маркеров, объектов, областей и Стен;
- записи реестра дополняют backing, не копируя HP и координаты;
- поиск, фильтры, понятные поля, отдельный список потерянных связей;
- переход к объекту на поле и сохранённые операции связи/удаления Нарратора;
- player projection скрывает закрытые backing и идентификаторы.

Первоначальный результат скрывал все видимые backing игрока, если проекция реестра
была пустой. При ошибке `projectScene` использовалась полная `Scene`; имя владельца
также искалось в полной Сцене. Эти fallback могли раскрыть скрытые сведения.

Исправлено:

- видимые backing выводятся независимо от наличия записей реестра;
- player projection закрывается с понятным состоянием при ошибке и не подставляет
  полную Сцену;
- владельцы ищутся только в проецированной Сцене;
- authoritative `resolve` не вызывается при player render;
- тест покрывает пустую проекцию реестра при видимом маркере.

Остаток: заполненный браузерный сценарий с пятью массовками, маркером, областями,
Стенами, удалением, reload и undo. Единое каскадное удаление относится к L05/L07.

## L03 — мобильная компоновка

Приняты адаптивные правила для 390×844 и промежуточной ширины. Верхний этап,
кнопки цели/карты, поле и нижняя навигация остаются доступными. Desktop правила
не заменены. Тринадцать локальных PNG сначала попали в коммит агента, затем были
удалены отдельным cleanup-коммитом; они не являются частью репозитория.

Совместная проверка L02+L03 на пустой Сцене при 390×844 показала доступные поиск,
фильтр, форму связи и кнопку закрытия панели, без ошибок консоли. Заполненный
сценарий и 768/1280 после объединения ещё следует пройти в L11.

## Следующая волна

Следующий рой нельзя пускать одновременно в общие UI-файлы.

1. **L04, последовательная после этой интеграции:** UI завершения Сопротивления и
   последствия, выбор конкретной потери, исправление Нарратора, reload и экспорт.
   Владеет `lionwing-ui.js`; при необходимости получает отдельный lock на экспорт.
2. **L05, параллельно:** read-only план единого удаления в новом модуле и тестах.
   Не подключает кнопки и не редактирует общие handlers.
3. **L06, параллельно:** fixture долгого боя, 250+ событий, checkpoint/export/reload,
   21+ undoable изменений и доказательство разных слоёв восстановления.

После принятия L05 запускается L07 — подключение удаления. L08 (лист и ручные
Техники) и L09 (небольшая локализация) можно планировать параллельно только после
освобождения их файлов. L10 и L11 остаются последовательной сетевой и браузерной
приёмкой на одном интегрированном commit.

Ключевое правило следующего роя: агент получает один ограниченный контракт и один
набор файлов. Статус «тесты зелёные» не считается приёмкой без проверки истинного
UI-пути, сохранения результата и границы авторитета.
