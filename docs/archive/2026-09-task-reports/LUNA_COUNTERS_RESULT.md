# LionWing: строгие счётчики — результат блока

Дата: 2026-09-08. Ветка: `codex/lionwing-rules-kernel`.

## Реализовано

- Существующие часы правил и альтернативные ресурсы приведены к общей сериализуемой схеме: устойчивый ID, тип, владелец, источник, правило, область, срок, минимум, максимум, начальное и текущее значение, порог.
- Публичные операции LionWing поддерживают создание, настройку, установку, изменение, сброс, переименование, изменение размера и удаление с атомарной строгой валидацией.
- Достижение порога записывается один раз только при переходе снизу к порогу. Replay события и повторная установка полного значения не создают новый переход; сброс ниже порога снова разрешает переход.
- Метаданные сохраняются нормализатором Сцены и входят в обычные снимки отката.
- Общие часы Сцены получили `add`, `reset`, явное текущее значение и те же метаданные; UI позволяет задать значение и сбросить часы.
- Сетевой путь использует существующую проверку владения LionWing: игрок не может подменить участника и изменить чужой счётчик; часы Сцены остаются операциями Нарратора.

## Исправление после ревью

Полный тест обнаружил несовместимость с уменьшением часов «Гордость»: сохранённое поле `max` перекрывало явно переданный новый `size`. При нормализации явный `size` теперь имеет приоритет. Существующий сценарий Braggart проверяет уменьшение 6 → 4.

## Проверки

- `node tests/lionwing-counters.mjs`
- `node tests/scene-engine.mjs`
- `node --check` для затронутых браузерных модулей
- полный `npm test`
- `git diff --check`

Новый тест включён в `test:families` и проверяет два достижения порога через сброс, replay, строгие границы, атомарный отказ, переименование без смены ID, JSON reload, сохранность снимка, чужой сетевой запрос и счётчик Сцены.

## Граница блока

Порог создаёт типизированный факт/событие, но конкретные Техники к нему пока не подключены. Вычисляемые ауры, сегментное движение и автоматизация адаптеров остаются отдельными блоками.
