# Luna execution: сохранённое продолжение последствий

Дата: 2026-09-07

## Сделано

В `lionwing-execution.js` добавлен малый чистый сериализуемый курсор состояния
исполнения: `openCursor`, `advanceCursor`, `resizeCursor`, `waitCursor` и
`resumeCursor`. Он хранит только ID цепочки, владельца/отвечающего, позицию,
общее число шагов, результаты и ожидающий `choiceId`; функций, DOM и второй
очереди в сохранении нет.

В `lionwing-engine.js` курсор подключён к уже существующей
`scene.lionwing.deferred`. Оплата составной цены проходит один раз: если потеря
Здоровья вызывает Рану и Сопротивление, хвост операций сохраняется. Ответ
снимает ожидание и продолжает очередь; следующий урон может открыть новое
Сопротивление, после которого оставшийся хвост применяется один раз. Курсор
переносится через `pause-chain`/`resume-chain`, очищается для пустого хвоста,
скрывается в проекции игрока и явно отклоняет повреждённый или неизвестный
формат сохранения. Для старых сцен без поля используется существующий
`deferred`, курсор создаётся на границе ответа.

## Воспроизведённый пробел и проверка

До этой правки сохранение, в котором был заменён ID ожидающего choice при
сохранённом хвосте, принимало такой же ответ участника и продолжало чужой
контекст. Проверка старой версии ядра на сценарии с оплатой Здоровьем дала
`accepted: true`, урон по хвосту применился; текущая версия отклоняет его как
несоответствие курсору. Это связывает ответ с сохранённым продолжением поверх
существующей очереди, не дублируя её.

Новый сценарный тест проверяет:

- цена `Здоровьем + Фокус` вызывает первое Сопротивление до первого отложенного
  последствия;
- JSON reload через `app-core.js` `sceneCore` сохраняет курсор и `deferred`;
- второе последствие открывает ожидание другого отвечающего;
- stale/foreign/подменённый responder choice и удалённый отвечающий отклоняются;
- повтор того же ID события не повторяет последствия;
- автором курсора может быть `scene` или отсутствующий автор;
- старое сохранение без курсора продолжает через `deferred`;
- завершённый курсор не остаётся при пустом хвосте.

## Ограничения и интеграция

`app-core.js`, UI, geometry, package/index/sw и сетевой код в этом блоке не
изменялись. Текущий `sceneCore` уже копирует весь `scene.lionwing`, поэтому
`executionCursor` и `deferred` проходят нормализацию без отдельного поля. Если
в будущем нормализатор начнёт фильтровать `lionwing`, нужно сохранить эти поля
вместе с `choices` и `deferred`; менять `app-core.js` сейчас не требуется.

Не реализованы compound Health cost, массовая автоматизация Техник и UI
«Собрать бросок». Новые тесты не добавлены в `package.json` по границе задания;
focused test запускается отдельной командой выше. Неподдерживаемый или
повреждённый курсор даёт явный отказ, а не тихо удаляется.
