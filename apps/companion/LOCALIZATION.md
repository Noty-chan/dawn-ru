# Локализация компаньона

Компаньон сейчас выпускается только на русском языке. Английская версия отложена,
но новые данные, механики, сетевые события и элементы интерфейса должны сохранять
возможность перевода без переписывания ядра.

## Главный принцип

Механика опирается на стабильные `id`, а не на видимый текст. Идентификаторы входят
в формат сохранений и сетевой протокол, поэтому не переводятся и не меняются после
публикации. Уже существующие идентификаторы с русскими сегментами также остаются
неизменными ради совместимости. Для удобства кода допускаются английские
семантические псевдонимы, например `ACTION_IDS.spell`.

Запрещено добавлять проверку вида `action.name === "..."`, ветвиться по
переведённому названию Эффекта или передавать локализованную строку как единственный
идентификатор правила. Используйте `id`, `actionIs`, `actionByKey`, `sourceActionId`
и другие семантические поля. Старые сцены принимаются через единственный
`canonicalActionId`-адаптер; рабочее ядро и интерфейс уже не ветвятся по названиям.
Тест локализации запрещает возвращать такие сравнения.

## Интерфейсные строки

`localization.js` предоставляет `window.DAWN_I18N`:

- `t(key, params, { fallback })` — строка интерфейса;
- `field(entity, field)` — локализуемое поле справочных данных;
- `eventText(event)` — текст события по семантическому ключу;
- `setLocale(locale)` и `getLocale()` — выбор зарегистрированного языка.

Ключи записываются на английском в точечной нотации (`scene.prompt.cancel`).
Русский каталог `locale-ru.js` обязателен и служит запасным. Новые строки не нужно
склеивать из фрагментов: порядок слов и целая фраза принадлежат каталогу, значения
подставляются через `{actor}` и другие именованные параметры.

Полная миграция уже существующего русского интерфейса не является условием текущего
этапа. Но новый или существенно изменённый общий текст следует сразу помещать в
каталог.

## Справочные данные

`data.js` остаётся генерируемым файлом. Канонический русский текст хранится в
`source/translation/`, а генератор объявляет `sourceLocale: "ru"` и
`availableLocales: ["ru"]`.

Будущий перевод добавляется к сущности, не заменяя её механические поля:

```js
{
  id: "stable.id",
  name: "Русское название",
  text: "Русский текст",
  i18n: { en: { name: "English name", text: "English text" } }
}
```

Читать отображаемые поля следует через `DAWN_I18N.field(entity, "name")`. Числа,
формулы, семейства автоматизации и ссылки на правила не дублируются в `i18n`.
Оригинальная книга в `source/original/` является источником для будущего английского
каталога, но извлечённый из PDF текст обязательно сверяется вручную по странице.

## События, журнал и сеть

Событие может содержать `messageKey`, объект `messageArgs` и русский
`messageFallback`. По сети и в сохранение уходит ключ с аргументами; каждый клиент
отображает его через `eventText`. Резервный текст сохраняет читаемость старого клиента
и журнала. Решение правил нельзя восстанавливать из `messageFallback`, `name` или
`text`.

## Как позднее добавить английский

1. Создать `locale-en.js`, зарегистрировать `en` и подключить файл рядом с русским
   каталогом в `index.html`, `sw.js` и тестах.
2. Добавить проверенные `i18n.en` в генератор данных; обновить `availableLocales`.
3. Последовательно вынести оставшиеся строки интерфейса и журнала в каталоги.
4. Удалить оставшиеся ветвления по отображаемым именам из механики и адаптеров.
5. Добавить выбор языка, сохраняемый отдельно от Сцены, и прогнать один и тот же
   сценарный набор на `ru` и `en`.

До выполнения этих шагов переключатель языка пользователю не показывается.

## Проверка изменений

- Перевод текста не меняет результат механики, `id` события или состояние Сцены.
- Отсутствующий перевод падает обратно на русский, затем на явный fallback/ключ.
- Параметры сообщений валидируются и не содержат вычисляемую механику.
- Новый корневой каталог подключён в HTML, service worker и QA-загрузчик.
- После изменения источников выполняются `npm run data`, `npm run map` и `npm test`.
