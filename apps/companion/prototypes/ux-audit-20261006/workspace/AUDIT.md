# Оболочка и рабочий контекст · независимый аудит

База: `e3e6f182b100d3899ee274f0f7d732483d179570`. Аудит исходников checkout, 06.10.2026. Поскольку checkout общий, незавершённые чужие изменения не правились. Production не менялся этим агентом. Ниже доказательства из исходников; оценка неудобства и сценарии, ещё не пройденные в браузере, отмечены отдельно.

## Findings

1. **P1 · Редактор сам закрывается при завершении сборки.** `hero-ui.js:116,309`: без сохранённого предпочтения `complete ? "sheet" : "builder"` пересчитывается при рендере. Историческое browser-наблюдение: audit 05.10 UI-01. Воспроизведение: новый герой без предпочтения → заполнить последнее обязательное поле. Исправление: выбрать начальный вид один раз и переключать только явно. В черновике режим редактора всегда явный. Сегодня сценарий **not-run**.
2. **P2 · Подсказка отправляет пользователя в другой рабочий раздел без явного возврата к исходному действию.** `app-workspace.js:83–91`: ссылки вызывают `setMode(mode,{hash})`; `app-navigation.js:65–98` сохраняет прокрутку и панели, но не создаёт кнопку «вернуться к действию». Это не потеря игровых данных: navigation явно оставляет draft существующему контроллеру. Гипотеза UX: при чтении главы пользователь должен помнить, откуда пришёл. Repro: действие → справочная ссылка → глава → вернуться к действию. Исправление: справка в диалоге + явный возврат и переход в полные Правила.
3. **P2 · Навигационная память не сохраняет фокус исходного действия.** `app-navigation.js:70–73,89–95` capture/restore содержит scroll/hash/panels; focused control отсутствует. Гипотеза для клавиатуры: восстановление места прокрутки не возвращает точку ввода. Repro: сфокусировать действие, открыть правило, вернуться, Tab. Исправление: сохранять исходный элемент/стабильный ключ; диалог черновика возвращает фокус.
4. **P2 · Активный герой визуально привязан к разделу сборки.** `app-workspace.js:48–51`: `.hero-switcher` показывается только при `mode === "build"`. Доказательство — условие видимости; гипотеза — в Правилах/Справочнике трудно помнить, чей контекст открыт. Repro: герой Нари → Инструменты → Справочник → определить героя без возврата. Исправление: компактная постоянная строка героя и роли над рабочим пространством.
5. **P2 · Файлы героя доступны только в одном разделе.** `index.html:80–83`, `app-workspace.js:49`: импорт/печать лежат в раскрытии sidebar, скрытом вне build. Repro: находясь в Справочнике, найти печать текущего героя. Исходники подтверждают размещение, затруднение — гипотеза. Исправление: один файловый маршрут из листа и настроек с явным текущим героем.
6. **P2 · Игровой лист тяжёлый ещё до чтения содержания.** `hero-ui.js:305`, `app.css:314`: identity min-height 170px, portrait 116×142, heading до 3.4rem, dashboard из многочисленных карточек, группы техник открыты по умолчанию (`hero-ui.js:299`). Гипотеза: первый экран отдан идентификации и декоративному весу вместо доступных действий. Repro: открыть полный лист 1440/390, посчитать сколько шагов нужно до техники. Исправление: однострочная идентичность, текущие/максимальные ресурсы, рабочие строки; подробности закрыты.
7. **P2 · Читабельность и цели управления листа слишком малы.** `app.css:314,318`: описания местами .64–.72rem (10.2–11.5px), resource buttons 24×24px. Исходники подтверждают размеры; промахи пальцем — гипотеза. Repro: 390px, прочитать описание и изменить Стресс одним касанием. Исправление: основной текст 16px, secondary 14px, мобильные действия 44px.
8. **P2 · Печать представляет другой вид, чем видимый игровой лист.** `app-builder-events.js:95` просто `window.print()`, `app.css:317` скрывает `.hero-sheet-view` и показывает builder `.sheet-panel`. Это может быть правильным источником печати; UX-гипотеза — пользователь не знает, что получит. Repro: игровой лист → печать → сверить ресурсы/техники и пагинацию. Исправление: явный предпросмотр компактного листа. Реальная печать **not-run**.
9. **P3 · Стол находится в центре порядка разделов, но постоянной контекстной точки возврата нет.** `index.html:25–30` уже использует правильный порядок Герой→Инструменты→Стол→Правила→Справочник. Не предлагается «исправлять» порядок, который уже правильный. `app-workspace.js:53` навигационная rail скрыта в play/reference. Гипотеза: центральность должна быть дополнительно выражена визуально и через контекстный возврат. Черновик выделяет центральную вкладку и сохраняет draft.

## Foundation и направление

Прочитаны CODEX.md корня/apps/companion, ARCHITECTURE.md, LOCALIZATION.md, TECHNIQUE-AUTOMATION.md, TECHNIQUE-REVIEW.md, предыдущий audit и перечисленные production UI модули. Не переносить данные/механику 0.9 в LionWing. Это UX-макет, а не альтернативное ядро правил.

Визуальное направление: светлая бумага, зелёные рабочие акценты, разделители вместо вложенных карточек. Стол — стартовый раздел и центр глобальной навигации. Текущий герой/роль доступны во всех разделах; редактор явно переключается в игру. Справочник — читабельные поисковые строки с типом; правило открывается поверх исходной задачи. Полный переход к Правилам оставляет явную кнопку возврата.
