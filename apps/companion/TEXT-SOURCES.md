# Источники текстов и версии

Компаньон различает язык интерфейса, язык справочных данных и редакцию книги.
Эти понятия нельзя сводить к одной строке версии.

## Четыре независимые версии

1. `VERSION` в корне репозитория — версия русского релиза проекта.
2. `DAWN_DATA.schemaVersion` — версия структуры генерируемых данных. Она меняется
   только при несовместимом изменении формы данных.
3. `source/text-sources.json` — редакции текстовых источников. Русский перевод
   имеет редакционную версию, английский оригинал до появления официального
   номера однозначно определяется полным SHA-256 файла.
4. `__BUILD_VERSION__` — версия развернутой сборки приложения. Она не является
   версией правил или перевода.

Сохранения и сетевые события продолжают ссылаться только на стабильные ID правил.
Ни редакция источника, ни язык отображения не входят в идентификатор сущности.

## Статусы источников

- `canonical` — источник, из которого сейчас генерируются основные поля сущностей;
- `reference` — первоисточник для сверки, ещё не готовый к автоматической публикации;
- `reviewed` — будущий постранично сверенный текст, пригодный для генерации языка.

Актуальный английский источник — LionWing Edition с ID
`dawn-en-lionwing-cb2f8e67`. Старый PDF зарегистрирован отдельно как
`dawn-en-9ce6d8d6` со статусом `obsolete-reference`. Автоматическое извлечение всё
равно требует постраничной проверки и не выдаётся пользователю напрямую.

Платная LionWing PDF хранится только локально и исключена из Git. Повседневный
канонический источник для перевода находится в
`source/editions/dawn-en-lionwing-cb2f8e67/canonical/`: техники разнесены по
Архетипам, остальные домены лежат в отдельных JSON, состав и количества записаны
в `manifest.json`. `extracted-companion.json` остаётся цельным снимком для
воспроизводимости, а браузерный `edition-lionwing.js` генерируется из того же
объекта. PDF нужен только для спорных мест и повторной генерации; в Git и Pages
попадают рабочие данные, но не файл книги.

Результат сравнения английского 0.9 с английским LionWing записывается в
`edition-comparison.json`. Практическая очередь переводчика находится в
`translation-worklist.json` и `TRANSLATION-WORKLIST.md`: старый русский текст
переиспользуется только для полностью неизменного английского источника.
`translation-ru.scaffold.json` содержит безопасную заготовку: изменённые записи
пусты, а перенесённые помечены `reused-needs-review` и не подключены к runtime.

## Как добавляется английский текст

Английский корпус берётся из `canonical/`. Для каждой сущности сохраняется
стабильный ID, а проверенные русские поля добавляются в отдельный языковой слой:

```js
{
  id: "stable.id",
  name: "Русское название",
  text: "Русский текст",
  i18n: { en: { name: "English name", text: "English text" } }
}
```

Поля механики, числа, формулы и профили автоматизации не копируются в языковой
слой. Русская 0.9 не изменяется при таком переносе. В LionWing допустим явно
помеченный fallback отображения на русскую механику, но он не считается переводом
или подтверждением совместимости редакций.

## Рекомендуемый порядок

1. Техники и Архетипы (`pages 65-99`) — самый полезный первый вертикальный срез.
2. Базовые действия, Эффекты и правила боя (`pages 20-64`).
3. Мировоззрения, Дары и Связи (`pages 37-51`).
4. Инструменты Нарратора и враги (`pages 100-124`).
5. Оставшийся интерфейс, журнал, поиск и метаданные PWA.

Каждый срез должен проверять совпадение набора стабильных ID между RU и EN,
наличие обязательных полей и отсутствие влияния выбранного языка на состояние
Сцены.
