# Мягкая интеграция новой редакции

`changes.json` — единая очередь изменений книги, русского перевода и компаньона.
Одна запись описывает одно минимальное смысловое изменение:

```json
{
  "id": "change-0001",
  "stableId": "powerhouse.berserker",
  "oldPages": [65],
  "newPages": [66],
  "kind": "mechanics",
  "fields": ["levels.1.text"],
  "summaryEn": "Short factual description",
  "status": {
    "sourceReviewed": true,
    "translation": "draft",
    "mechanics": "pending",
    "companion": "pending"
  },
  "notes": ""
}
```

Допустимые `kind`: `editorial`, `terminology`, `addition`, `removal`, `mechanics`,
`layout`. Статусы перевода, механики и компаньона: `not-applicable`, `pending`,
`draft`, `reviewed`, `published`.

Изменение не попадает в публичный английский билдер, пока английский текст не
сверен с новой страницей. Изменённая механика не заменяет текущую русскую механику,
пока отдельно не подтверждены перевод и адаптер компаньона.

## Иерархия источников для ежедневной работы

1. `canonical/` — английский канон по сущностям; основной вход для перевода.
2. `edition-comparison.json` — машинная очередь сопоставления 0.9 и LionWing.
3. `translation-worklist.json` — решение `reuse-existing-ru`, `retranslate`,
   `translate-new` или `retire` для каждой переводческой единицы.
4. `translation-ru.scaffold.json` — стартовые пустые слоты и только безопасные
   кандидаты переноса; этот файл сам по себе не подключается к приложению.
5. `changes.json` — только рассмотренные человеком решения и их статусы.
6. Локальные PDF — арбитраж спорного места и повторная генерация, не рабочая
   база перевода и не публикуемый артефакт.

Сначала сравниваются английские тексты 0.9 и LionWing. Старый русский перевод
можно перенести только при неизменном английском оригинале. Любое изменение
английского поля ставит всю сущность в очередь нового перевода; влияние на
механику при этом всё равно подтверждается отдельно.
